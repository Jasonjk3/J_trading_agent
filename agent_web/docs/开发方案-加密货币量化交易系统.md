# 加密货币量化交易系统 - Vue3 前端开发方案

## 一、项目概述

基于 Vue 3 的**静态前端**加密货币量化交易系统，先完成页面、路由、Mock 数据与前端状态设计，后续再接入真实后端接口。技术栈建议：Vue 3 + TypeScript + Vue Router + Pinia + 图表库（如 ECharts） + UI 组件库（如 Element Plus / Naive UI）。

---

## 二、功能模块与页面规划

### 1. 系统账号管理

**目标**：管理登录本系统的用户账号、角色与权限（静态阶段仅做界面与 Mock）。

**子功能**：
- **登录 / 登出**：登录页、Token 模拟、登出清除状态。
- **用户列表**：表格展示用户（用户名、角色、状态、创建时间等），支持搜索、分页。
- **用户新增/编辑**：表单（用户名、密码、角色、状态、备注等）。
- **角色管理**（可选）：角色列表、权限勾选（如：只读、交易、配置交易所等）。
- **个人中心**：当前用户信息、修改密码、安全设置（静态展示）。

**数据与接口预留**：
- 用户列表：`GET /api/users`
- 用户增删改：`POST/PUT/DELETE /api/users/:id`
- 登录：`POST /api/auth/login`，登出：`POST /api/auth/logout`
- Mock：本地 JSON 或 MSW 模拟上述接口。

**页面**：登录页、用户管理（含列表+表单）、角色管理（可选）、个人中心。

---

### 2. 交易所账号配置管理

**目标**：管理用于量化交易的交易所 API 密钥（API Key/Secret），仅前端展示与表单，不存真实密钥。

**子功能**：
- **交易所列表**：支持多个交易所（如 Binance、OKX、Bybit 等），表格展示：交易所、备注名、绑定状态、最后校验时间。
- **添加/编辑配置**：选择交易所、填写 API Key、API Secret、Passphrase（如需要）、备注；可勾选“仅读权限”等。
- **连接测试**：按钮触发“测试连接”，前端只做 Mock 成功/失败提示，预留 `POST /api/exchange/verify`。
- **启用/禁用**：单条配置的启用开关，便于暂停某交易所而不删除配置。

**数据与接口预留**：
- 配置列表：`GET /api/exchange-accounts`
- 新增/更新：`POST /api/exchange-accounts`、`PUT /api/exchange-accounts/:id`
- 删除：`DELETE /api/exchange-accounts/:id`
- 验证连接：`POST /api/exchange-accounts/:id/verify`

**安全**：前端不展示完整 Secret，仅展示脱敏（如 `****xxxx`）；真实密钥仅通过 HTTPS 提交给后端。

**页面**：交易所账号配置（列表 + 新增/编辑抽屉或弹窗）。

---

### 3. 首页与数据分析图表展示

**目标**：仪表盘式首页，汇总资产、收益、持仓与关键指标，并用图表做数据分析。

**子功能**：
- **总览卡片**：总资产、今日/本周/本月收益、今日交易次数、当前持仓数等（数字来自 Mock）。
- **资产分布图**：饼图或环形图（各币种或各交易所占比）。
- **收益曲线**：折线图展示累计收益或每日收益随时间变化。
- **持仓占比**：饼图或条形图（各标的持仓市值占比）。
- **行情/资金流向**（可选）：如 BTC/ETH 等价格走势小图或简单 K 线，用 ECharts 等实现静态示例。

**数据与接口预留**：
- 总览：`GET /api/dashboard/summary`
- 资产分布：`GET /api/dashboard/asset-distribution`
- 收益曲线：`GET /api/dashboard/profit-curve?period=7d|30d`
- 持仓占比：`GET /api/dashboard/position-distribution`

**页面**：首页（Dashboard），一个页面多区块布局，每个图表一个组件便于后续接真实接口。

---

### 4. 持仓管理

**目标**：展示当前各交易所、各币种的持仓（数量、成本、市值、盈亏等）。

**子功能**：
- **持仓列表**：表格字段如：交易所、交易对、方向（多/空）、数量、成本价、当前价、市值、未实现盈亏、收益率。
- **筛选**：按交易所、币种、方向筛选。
- **汇总**：顶部或底部展示总市值、总未实现盈亏。
- **操作预留**：如“平仓”“加仓”按钮，静态阶段可置灰或弹窗提示“接口未接入”。

**数据与接口预留**：
- 持仓列表：`GET /api/positions`，支持 query：exchange、symbol、side。
- Mock：多条持仓记录，含主流币种与不同交易所。

**页面**：持仓管理（单页列表 + 筛选 + 汇总）。

---

### 5. Agent 交易

**目标**：对“交易 Agent”进行配置与监控（如策略开关、参数、运行状态），并在单页内集中展示收益曲线、持仓/委托与 Agent 操作记录、思维链详情；静态阶段只做界面与 Mock 状态。

**页面布局**（以某 Agent 运行/监控页为例）：
- **左上**：**收益曲线** — 该 Agent 的累计收益或区间收益随时间变化的折线图。
- **左下**：**当前持仓** 与 **当前委托** — 用 Tab 切换展示；左侧整体为“实时状态”区域。
- **右侧**：**Agent 操作记录** — 该 Agent 的最近操作列表（下单、平仓、调仓等）；下方或可展开区域为 **思维链详情**（Chain-of-Thought），展示单条操作对应的推理步骤、依据与结论。

**子功能**：
- **Agent 列表**：展示已配置的 Agent（名称、策略类型、绑定交易所、状态：运行中/已停止、最近运行时间），点击进入上述布局的监控/运行页。
- **Agent 配置/编辑**：策略类型选择、关联交易所、参数表单（如阈值、仓位比例、止盈止损等），全部用 Mock 数据。
- **启停控制**：开始/停止按钮，前端只做状态切换与 Toast，预留 `POST /api/agents/:id/start`、`POST /api/agents/:id/stop`。
- **收益曲线**：左上图表组件，数据来源 Mock 或预留 `GET /api/agents/:id/profit-curve?period=7d|30d`。
- **当前持仓 / 当前委托**：左下 Tab 切换，复用持仓与订单数据结构，可请求 `GET /api/positions`、`GET /api/orders` 并按当前 Agent/策略过滤，或预留 `GET /api/agents/:id/positions`、`GET /api/agents/:id/orders`。
- **操作记录与思维链**：右侧列表 + 详情；预留 `GET /api/agents/:id/operations?limit=50`，单条含操作类型、时间、标的、结果等；思维链详情可内嵌在操作记录条目中（展开）或由 `GET /api/agents/:id/operations/:opId/chain-of-thought` 获取。

**数据与接口预留**：
- 列表：`GET /api/agents`
- 增删改：`POST /api/agents`、`PUT /api/agents/:id`、`DELETE /api/agents/:id`
- 启停：`POST /api/agents/:id/start`、`POST /api/agents/:id/stop`
- 收益曲线：`GET /api/agents/:id/profit-curve?period=7d|30d`
- 当前持仓/委托：`GET /api/agents/:id/positions`、`GET /api/agents/:id/orders`（或复用 `GET /api/positions`、`GET /api/orders` 加过滤）
- 操作记录：`GET /api/agents/:id/operations?limit=50`
- 思维链详情：`GET /api/agents/:id/operations/:opId/chain-of-thought` 或内嵌在 operations 响应中
- 日志：`GET /api/agents/:id/logs?limit=50`（可选，与操作记录二选一或并存）

**页面**：Agent 列表、Agent 配置/编辑（抽屉或独立页）、**Agent 运行/监控页**（左：收益曲线 + 持仓/委托 Tab；右：操作记录 + 思维链详情）。

---

### 6. 交易记录

**目标**：历史订单与成交记录查询与导出预留。

**子功能**：
- **订单/成交列表**：表格字段如：时间、交易所、交易对、方向、类型（市价/限价）、数量、价格、成交额、手续费、状态。
- **筛选**：时间范围、交易所、交易对、方向、状态。
- **分页**：前端分页或预留“服务端分页”参数。
- **导出**：按钮“导出 CSV/Excel”，静态阶段可做前端生成 Mock 数据的导出，后续改为调用后端导出接口。

**数据与接口预留**：
- 订单列表：`GET /api/orders`，query：startTime、endTime、exchange、symbol、side、page、pageSize。
- 成交明细：`GET /api/trades` 或合并在订单详情中。
- 导出：`GET /api/orders/export` 或前端先实现 CSV 导出。

**页面**：交易记录（单页，Tab 或筛选区分订单/成交）。

---

### 7. 收益分析统计

**目标**：从多维度统计与展示收益，支持时间范围、交易所、币种等筛选。

**子功能**：
- **收益概览**：选定时间范围内的总收益、总手续费、净收益、收益率（相对初始资金或总投入）。
- **收益趋势图**：折线图按日/周汇总收益。
- **维度分析**：按交易所、按币种、按策略（若后端有）的收益分布（表格+柱状图）。
- **筛选**：时间范围、交易所、币种、Agent/策略。
- **资金曲线**：账户权益随时间变化曲线（可与收益曲线同图或分图）。

**数据与接口预留**：
- 收益汇总：`GET /api/analytics/profit-summary?from=&to=&exchange=`
- 收益趋势：`GET /api/analytics/profit-trend?period=day|week`
- 按维度：`GET /api/analytics/profit-by-exchange`、`/profit-by-symbol`

**页面**：收益分析（单页多区块：概览卡片 + 趋势图 + 维度表格/图）。

## 三、非功能设计建议

### 3.1 路由与布局

- **布局**：主布局（侧边栏 + 顶栏 + 内容区），登录页、错误页独立布局。
- **路由**：  
  - `/login`  
  - `/` 重定向到 `/dashboard`  
  - `/dashboard` 首页  
  - `/users` 用户管理  
  - `/exchange-accounts` 交易所配置  
  - `/positions` 持仓管理  
  - `/agents` Agent 列表；`/agents/:id` 运行监控页（左上收益曲线、左下持仓/委托 Tab、右侧操作记录与思维链）；配置/编辑为抽屉或 `/agents/:id/edit`  
  - `/orders` 交易记录  
  - `/analytics` 收益分析  
  - `/profile` 个人中心  

### 3.2 状态管理（Pinia）

- **用户**：user、token、permissions，登出清空。
- **交易所配置**：列表缓存，便于在持仓、Agent 等下拉框复用。
- **可选**：Dashboard 数据、当前选中的时间范围等可放 store，便于多组件共享。

### 3.3 Mock 与联调

- **方式一**：在 `src/mocks/` 下放 JSON，请求时通过环境变量或 axios 拦截器指向 Mock 数据。
- **方式二**：使用 MSW（Mock Service Worker）在浏览器内拦截相同 path，返回假数据。
- **约定**：所有接口 path、请求方法、请求/响应数据结构与后端文档对齐，便于后续只替换 baseURL 或关闭 Mock 即可接真实接口。

### 3.4 权限与菜单

- **静态阶段**：菜单根据“角色”写死几种方案即可（如管理员看全部，交易员隐藏用户管理）。
- **接口预留**：菜单可来自 `GET /api/user/menus` 或由 permissions 前端生成菜单，便于后端接入后统一权限。

### 3.5 图表与 UI

- **图表**：ECharts 或 Chart.js，封装成 Vue 组件（如 `ProfitChart.vue`、`AssetPieChart.vue`），接收 props 数据，便于后续接真实 API。
- **UI**：Element Plus / Naive UI / Ant Design Vue 择一，表格、表单、日期范围、选择器等统一用同一套，保证风格一致。

### 3.6 响应式与主题

- 侧边栏可折叠，表格与图表在小屏下可横向滚动或隐藏次要列。
- 可选：明/暗主题切换，主题变量用 CSS 变量或 UI 库主题配置。

## 五、后续接入后端时注意点

1. **接口**：保持 path、method、请求体/查询参数与现有 Mock 一致，仅替换数据源。
2. **认证**：登录后保存 token，请求头统一加 `Authorization: Bearer <token>`，拦截 401 跳转登录。
3. **错误**：统一处理 4xx/5xx 与业务错误码，Toast 或 Message 提示。
4. **敏感数据**：API Secret 等仅在后端存储与使用，前端不持久化明文。

按本方案可实现完整的静态前端，再在接口层做最小改动即可接入后端。
